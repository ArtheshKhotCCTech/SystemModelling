# Result — compiled and verified Modelica models

Two of the four problem statements have a Modelica model here that compiles and reproduces its
reference trace. L3 (magnetic circuit) and L4 (NaCl evaporation) are not delivered
(`docs/specifications/FR-12-not-delivered.md`).

Each folder holds `model.mo` and two scripts that run it from that folder with OpenModelica and
MSL 4.0.0:

```
cd Result/L1_tank          # or Result/L2_room_co2
omc compile.mos            # checkModel + buildModel: "Check of ... completed successfully."
omc simulate.mos           # writes <package>.System_res.csv over the model's own experiment
```

Checked with OpenModelica 1.27.1 and MSL 4.0.0 on 2026-10-05: both compile with no error and
simulate to the end of their experiment.

## Opening them in OMEdit

`File → Open Model/Library File(s)` → `model.mo`, then open `System` (inside
`system_model` for L1, `room_co2_ventilation` for L2):

- **Diagram View** shows every component placed left to right in the direction things flow,
  with its name, and a line for every `connect` (fluid lines blue, real signals dark blue,
  Boolean signals magenta). A line that closes a feedback loop runs below the components.
- **Check Model** (right-click `System`) prints `Check of ... completed successfully.` in the
  Messages Browser; **Simulate** runs the built-in experiment and opens the plot view. Useful
  variables: `tk_101.h`, `tk_102.h`, `plc_101.state` (L1); `zon_201.C` (L2, 0.001519 is 1000 ppm).

The diagram is graphics only. The layout is generated, so it is tidy rather than hand-drawn.
Flattening each model with `omc` gives output byte-identical to the version without diagrams,
so the drawings changed no equation. `omc`'s graphical API (the one OMEdit draws from) reads
every placement, line and icon back without error. Rendering in the OMEdit window itself was not
checked from here: please confirm it by eye.

## L1 — Two-tank fill / transfer / drain (`L1_tank/`)

| | |
|---|---|
| **Where it comes from** | `specalive run` on the L1 bundle, from its inputs: extraction (replayed from the recorded LLM responses in `tests/fixtures/extract_cache/`), generation, compile, verify. No hand-written IR. |
| **Model** | `system_model.System`: 13 parts, 16 connections, a nine-state controller; 900 s experiment. |
| **Verified against** | `09_datasets/10_demo_run_900s.csv` and the TP-17 acceptance criteria. |
| **Result** | Exit 0, every gate passed. AC-02, AC-03, AC-05, AC-06, AC-08 PASS; AC-01, AC-04, AC-07 NOT CHECKED (timed from events, as in the golden IR). All 12 controller state changes, all valve changes and both tank levels match the reference within tolerance. |
| **How close** | Valve and state change times within 2 s (the tolerance is 2 s, so at the limit); tank 1 level within 0.0137 m of a 0.015 m tolerance, tank 2 within 0.0057 m of 0.0129 m. |
| **Caveat** | The recorded LLM responses are a selected sample (see `tests/adversarial/RESULTS.md`): a fresh run with new LLM answers does not reproduce this every time. |

## L2 — Room CO2 demand-controlled ventilation (`L2_room_co2/`)

| | |
|---|---|
| **Where it comes from** | Generated by `specalive generate` from the hand-written golden IR `tests/goldens/L2_co2.ir.json` (every value traced verbatim to the L2 bundle), then compiled and verified by `specalive compile` and `specalive verify`. |
| **Model** | `room_co2_ventilation.System`: well-mixed room, outdoor-air source, occupant CO2 source, exhaust boundary, sensor, normalisation and airflow gains, P controller with bias and limits, occupancy schedule; 24 h experiment at 60 s. |
| **Verified against** | `09_datasets/11_reference_run_24h.csv` and the CP-23 acceptance criteria. |
| **Result** | Peak room CO2 996.57 ppm (reference 996.52 ppm, 0.005 %), never above 1000 ppm; room CO2 within 1.25 ppm of the reference at every one of its 1441 samples; physical supply flow always positive and the source command always negative. AC-01 and AC-03 PASS at all 1458 samples; AC-02 NOT CHECKED (omc removes the constant's output from the result); AC-04 to AC-06 NOT CHECKED by design (arithmetic between signals, or a property of the log file). |
| **Why not the run from the inputs** | `specalive run` on the L2 bundle also produces a model that compiles, with every component value equal to the golden's, a peak of 996.57 ppm and the same sign convention. But the sources state the room's starting concentration only as "the outdoor concentration", which extraction does not resolve to a number, so that model starts the room at 0 ppm: it is up to 300 ppm low before 08:00 and within 1 ppm from 10:00. It is therefore not used here. |

## What "verified" does not cover

- SysML v2 for both models validates with the OMG Pilot Implementation (0 errors, 0 warnings);
  it is in the pipeline's run folders, not here, since only Modelica was asked for.
- The models are as faithful as the lightweight components they use: constant-flow ideal valves
  for L1, a well-mixed constant-mass room for L2 (`docs/design/ADR.md`, "Model representation").
